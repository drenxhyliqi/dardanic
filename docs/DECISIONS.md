# Decisions

Format: **date — decision.** Why.

- **2026-11-19 — Expo + Expo Router for the mobile app.** One TypeScript codebase for iOS and Android; file-based routing keeps screens easy to find.
- **2026-11-19 — TypeScript strict mode.** Catches mistakes before they run, which matters while learning.
- **2026-11-19 — Supabase (Postgres, Auth, Storage, Edge Functions).** One hosted backend covering the database, login, file storage and server code. Row Level Security keeps data safe at the database level.
- **2026-11-19 — TanStack Query for server data.** Handles caching, loading/error states and refetching, so screens stay simple.
- **2026-11-19 — pnpm workspaces monorepo.** The mobile app (and later the web app) share theme, i18n and types from `packages/shared`.
- **2026-11-19 — Shared code = theme, i18n, types only.** React Native UI components stay in `apps/mobile/components`, because they can't be reused directly by a Next.js web app.
- **2026-11-19 — ~~Bilingual from day one (sq + en).~~ Replaced: the app is English-only for now** (user decision; Albanian didn't fit). Text still lives in one file (`i18n/en.ts`), so adding a language later stays easy. The unused Albanian file was removed.
- **2026-11-19 — Deferred: Cloudflare Images/Stream, Expo Notifications, RevenueCat, Next.js web, PostHog, Sentry.** Added when the features that need them are built.
- **2026-11-19 — Expo SDK 58, app in `apps/mobile`, set up by hand from Expo's blank TypeScript template.** Only the packages we asked for; the default template adds many extras.
- **2026-11-19 — Theme and text live in `apps/mobile/theme` and `apps/mobile/i18n` for now.** No i18n library yet; move them to `packages/shared` when the web app or English arrives.
- **2026-11-19 — `@expo/vector-icons` for icons.** Expo's official icon pack: Apple/Google logos now, tab bar later.
- **2026-11-19 — Solid colours only, no glows.** User's design direction. Photos may fade into the background (React Native's built-in `backgroundImage: linear-gradient`, no library) for readable text.
- **2026-11-19 — System font (San Francisco on iPhone, Roboto on Android).** It's what Instagram and Facebook use for body text; no font files to load.
- **2026-11-19 — Intro animation uses React Native's built-in `Animated`.** Simple enough that Reanimated isn't needed yet.
- **2026-11-19 — Unbounded for headings (`@expo-google-fonts/unbounded` + `expo-font`).** Wide, geometric and modern, matching the wordmark. Body text stays on the system font.
- **2026-11-19 — Blue also marks confirmations** (e.g. the "Account created" pill), at the user's request; replaces an earlier green `success` colour.
- **2026-11-19 — Plan choice right after sign-up: Standard (free) / Professional (paid, for businesses).** Until auth and payments exist, sign-up buttons skip straight to this step and both plans continue into the app.
- **2026-11-19 — `expo-splash-screen` for the launch screen.** Native splash = dark background + D logo (configured in `app.json`), held until our in-app launch animation (`components/launch/LaunchScreen.tsx`) draws the same picture, fills a thin line, and fades into the welcome screen. Expo Go shows its own loader first; only real builds show the native splash.
- **2026-11-19 — `expo-image-picker` for the profile photo and banner.** Expo's official package; works in Expo Go and opens the system photo picker with a crop step. Only the photo library is used (camera and microphone permissions turned off in `app.json`).
- **2026-11-19 — Skeletons for loading.** Anything slow to appear shows pulsing `Skeleton` blocks (`components/ui/Skeleton.tsx`, built-in `Animated`, solid colour fade, no shimmer gradient) shaped like the real content; images not bundled with the app use `LoadingImage`. No extra package needed.
- **2026-11-19 — Vibe names live in `apps/mobile/data/vibes.ts`, not `i18n/en.ts`.** They're content (brands, models, styles), like the Kosovo city list, and will come from the server later. App wording (titles, buttons, filter names) stays in `en.ts`.
- **2026-11-19 — Intro after vibes: 3 steps (Community, Near you, Your garage) with a tilted, endlessly moving 3-column card carousel.** Built with React Native's `Animated` (no new package); each column is drawn twice and slides by one set so the loop has no jump. Cards use made-up sample people, places and builds (`data/intro.ts`) until real featured content exists. The carousel reuses `imageFade` so the text below stays readable.
- **2026-11-19 — Plate search is a must-build core feature.** Users can add their licence plate (optional per user) so others who spotted the car can find their profile. It will be built once the backend and messaging exist, with the safety rules listed in `docs/PROGRESS.md` (ownership check, message requests, block/report, search limits, 18+).
- **2026-11-19 — Onboarding data lives in a React context (`context/OnboardingContext.tsx`) until the backend exists.** Screens forget their state when you leave them, so the "account ready" screen needs a shared place to read the name from. Built into React, no new package; later it's what gets saved to Supabase.
- **2026-11-19 — "Account ready" screen greets by first name** (from the display name), falling back to the username. Its D logo sits exactly where the feed's top-bar logo is, so shrinking everything into it and fading to the feed looks continuous.
- **2026-11-19 — Profile picture rings.** Thin solid blue accent ring normally; a blue → violet → purple gradient ring (`storyRing` in `theme/colors.ts`) when the user has a story. The gradient is an approved exception to "solid colours only" (asked for by the user).
- **2026-11-19 — Light + dark theme, everywhere.** Settings → Theme: Light / Dark / Automatic (default, follows the phone). Warm-white light palette (`#F7F4ED` background, white cards, `#080B12` text, same blue). `ThemeProvider` picks the palette; components read it with `makeStyles` / `useColors`, so the whole app switches instantly. The choice is saved with `@react-native-async-storage/async-storage`. Single-colour logos are tinted with the text colour; the native splash has a light and a dark version (`app.json`), though it follows the phone's setting rather than the in-app choice.
- **2026-11-22 — A flame replaces the heart as DARDANIC's "like".** Works exactly like a like: one per person, tap to flame, tap again to unflame, double-tap a photo to flame it; posts show "1,284 flames". The icon is our own flame traced from the user's reference image (`assets/images/flame@3x.png` and `flame-outline@3x.png`, white images tinted by the theme, no new package): an outline before, filled red (`flame` token) once flamed, where only the outer flame is solid and the inner flame stays hollow; small pop on tap. (A first version with up to 10 "hype" presses, "+1"s, sparks and a layered fire-colour flame was tried and dropped by the user in favour of this simpler one.)
- **2026-11-22 — `expo-haptics` for a light vibration when you flame something** (user approved). Official Expo package, works in Expo Go.
- **2026-11-22 — Story viewer: card-stack switch between people + name card.** The leaving story shrinks back and darkens while the next slides over it, and the new person's avatar and name show briefly in the middle, so it's clear you moved to someone else (asked for by the user, deliberately not Instagram's cube). Built with React Native's `Animated` driven by the pager's scroll; no new package.
- **2026-11-22 — Comments open in our own bottom sheet** (`components/ui/BottomSheet.tsx`), not the native iOS sheet, because iOS shows native sheets as a floating card at partial height. Ours sits on the bottom edge, opens to 70% of the screen and slides up to full screen; height is animated so the comment field stays visible at every size. No new package.
- **2026-11-22 — Direct messages UI (no backend yet).** Inbox with Chats / Requests (requests = people you don't follow, incl. plate search, with Accept / Delete / Block and no reply until accepted), full-screen chats with grouped bubbles, day dividers, shared posts / meets / story replies, photos (`expo-image-picker`), double-tap to flame a message, typing dots, Seen / Sent, a New message screen and a red unread count on the Messages tab. Your own bubbles are solid blue (`primary`), a rule exception chosen by the user. Data lives in `context/MessagesContext.tsx` for now; the backend will need conversations, conversation_members (muted, last read), messages (text/photo/post/meet/story_reply), message_reactions, message_requests (pending/accepted/blocked + source), blocks, Realtime (messages, typing) and Storage (photos), all with RLS so only members can read a chat.
- **2026-11-23 — FindMe (the plate search, first called RoadConnect) built as UI with mock data.** Opened from 🔍 on the Feed (until there's a real search screen). Search a plate by country (🇽🇰 🇦🇱 🇲🇰 🇩🇪 🇨🇭 🇦🇹) → driver card → request with an optional note → Accept / Decline / Block → their public profile with Follow and Message. Also: Requests (received / sent), Your vehicles (add / edit / remove, colour, findable switch), FindMe settings, and a general Notifications screen behind 🔔. Keeps the safety rules from 2026-11-19: findable only after the plate is verified (registration photo) and switched on (off by default); the plate is only ever shown masked (01-•••-KA); a result shows photo, name, username and car only (no bio, city or other photos; the user chose this over showing the bio); "not found" looks the same whether the plate doesn't exist or isn't findable; 10 searches a day; block and report everywhere; 18+. Plate contacts no longer arrive as Messages requests (no duplicate).
- **2026-11-23 — Feature operations go through a service interface** (`services/<feature>/`): `FindMeService` lists every operation (search, requests, vehicles, verification, block, report, plus `subscribe` for live events); `mockFindMeService` fakes it with delays and its own "server" state; screens only use `FindMeContext`. Connecting Supabase later means writing a second implementation of the same interface and changing one export.
- **2026-11-23 — Car paint swatches live in `data/vehicleColors.ts`**, not the theme: they describe the car, not the app's look.
- **2026-11-23 — FindMe countries are shown by their plate code, not flags.** Emoji flags look different on every phone and clashed with the app's style; flag images add weight. Each country appears as its international code (RKS, D, CH, S…) in white on the blue strip from a European plate (`CountryCodeBadge`). 22 countries: Kosovo & neighbours (RKS, AL, NMK, MNE, SRB, GR, HR, SLO), Western Europe (D, CH, A, I, F, B, NL, UK, L, IRL) and the Nordics (S, N, DK, FIN), where most of the Kosovo-Albanian diaspora lives, with Popular (RKS, D, CH, AL) first. Picked from a searchable bottom sheet. North Macedonia uses its current code NMK. Plate-format checks per country are friendly guides, not legal rules.
- **2026-11-23 — FindMe is now also positioned as a way to meet people (dating-like), not only a car feature** (user decision; replaces the earlier "car feature, not meet people from traffic" positioning). A found driver's card opens their public profile, and profiles can show an Instagram handle under the bio (tappable, opens Instagram). The safety rules still apply: opt-in after verification, masked plates, 10 searches a day, block and report, 18+. Profiles' Follow button is full width with Message under it.
- **2026-11-23 — 🔍 opens Search & Explore; FindMe lives inside it.** Before typing: a FindMe card ("Spotted a car?"), filter chips (For you / Businesses / Meets / your top vibes) and an Instagram-style Explore grid of posts from people you don't follow; tapping a tile opens the post on its own page (same PostCard). Tapping the field shows recent searches (saved on the phone with AsyncStorage, max 15); typing shows matching People and Businesses with Follow. Ranking lives in `services/search` (mock today): popularity (flames, shares ×5; meets by people going) that fades with age, plus 2.5 points per vibe the post shares with you, and a little shuffle on refresh. A real backend can rank the same way (or smarter) behind the same interface.
- **2026-11-23 — Search is a hidden tab, so the bottom bar stays visible.** `app/(tabs)/search.tsx` with `tabBarItemStyle: { display: 'none' }`; the custom bar skips hidden tabs and shows no highlight while you're on one. Don't use `href: null` for this: in this Expo Router version it makes the route unreachable (redirects away). All search fields are rounded pills (`TextField round`).
- **2026-11-24 — One notifications list for everything** (`context/NotificationsContext.tsx` + `services/notifications`, mock today): follows (Follow back), flames on your posts and story (thumbnail), comments / replies / mentions (quoted), meets starting soon, and FindMe's notifications (adapted into the same shape, so FindMe keeps its own state). Grouped like Instagram ("leon_builds, granit.gt and 12 others flamed your post"), sections New / Today / This week / Earlier, filters All / Follows / Flames / Comments / FindMe, a small badge on the faces for what happened. The bell's red dot counts all unread. The backend will need a notifications table (actor ids, kind, target, read) with Realtime.
- **2026-11-24 — Public and private accounts.** Your own: Settings → Private account (saved on the phone, `PrivacyContext`), shown as a 🔒 by your name. Others: following a private account is a request they approve (button says "Awaiting"); only approved followers see their posts (others see "This account is private"); their posts never appear in For you or Explore for non-followers. Messages go straight through if the account is public, you follow each other, or you connected on FindMe; otherwise they land in their message requests and your chat says so. One shared `FollowContext` (Follow / Follow back / Awaiting / Following, `FollowButton`) used by profiles, search and notifications. Assumption to confirm with the user: seeing posts needs *you* to follow them (Instagram-style); direct messages need *both* to follow each other.
- **2026-11-24 — Profile actions move into a ••• menu; profiles suggest similar accounts.** Someone's profile shows one shorter, full-width Follow button; Message, Share profile (phone share sheet), About this account (joined, based in, account type), Block (confirm step; a blocked profile shows "You blocked …" with Unblock) and Report live in a ••• bottom sheet. "Suggested for you" cards (photo, name, reason, Follow, ✕ to remove) come from `searchService.suggestedAccounts`: a person's vibes are the tags on their posts; candidates rank by vibes shared with the profile (×3) plus popularity; you, people you follow and blocked accounts are left out. Blocking lives in `FollowContext` (and is passed on to FindMe).
- **2026-11-24 — Builds: minimal cards, full build pages.** On the profile's Builds tab (speedometer icon) each car is a minimal card: photo, role (+ Main), model, year, HP and 0–100 (project cars: a thin progress line). Tapping opens `app/build/[id].tsx`: hero photo, key numbers (HP, Nm, 0–100, top speed), build progress, power gain (stock → now), spec sheet (engine, drivetrain, gearbox, weight, power-to-weight, fuel), every mod grouped by category with where it was done (businesses link to their profile, or DIY), when and cost, total invested, and a build log timeline. Garage data lives in `data/garage.ts`; build parts in `components/build/`. Profile tabs: Posts (photo grid) · Text posts (reader icon) · Builds.
- **2026-11-24 — Feed filters are Your vibes / Near you / Meetings; meets get minimal cards and a full page.** Near you uses coordinates for Kosovo's cities (`data/places.ts`, `utils/geo.ts`): posts within 50 km of your city, meets within 30 km, nearest first; diaspora cities count as far. Meetings shows only meets, soonest first, finished ones hidden. A meet card shows only the photo (date tile, LIVE/Tonight), title, "time · place · distance", who's going and a small Going button; tapping opens `app/meet/[id].tsx` with details, About, Schedule, Rules, who's going, the host, and I'm going / Interested / Directions / Share fixed at the bottom. Going/interested is shared in `MeetsContext`.
- **2026-11-24 — Marketplace is car-only, enforced in layers.** The sell form only offers car categories (Cars, Parts, Wheels & tyres, Tools & garage, Car electronics, Accessories), with no "Other"; clothing and merch aren't allowed; each category asks for its own details (cars: year/km/fuel/gearbox; parts: what it fits + part number; wheels: size/bolt pattern/offset), and the seller confirms "This listing is car-related". Publishing goes through `services/marketplace` (interface + mock): the mock checks words (shoes, phones, hoodies, caps… → Not allowed; car words or a fitment → Live; unsure → Under review). Later the same `publish` call runs an AI check on photos + text in a Supabase Edge Function, so screens don't change. Reports, limits for new accounts and a moderation queue come with the backend. Items only, no services (businesses have profiles for that). Messaging a seller opens a normal chat.
- **2026-11-24 — Listings are free text in Albanian; autocorrect is off.** A listing is a seller-written title (the headline, e.g. "AUDI A6 VITI 2018 35 TDI, ME DOGAN") with the price under it, plus a description holding every detail. No structured details table (year, km, part number…); only an optional "Fits" for parts, wheels and accessories. All text inputs have autocorrect and spell check off (default in `TextField`, set on the other inputs), because people write in Albanian and the phone would "fix" it into English. All demo content people write (posts, comments, messages, meets, bios, listings, build notes) is in Albanian; the app's own UI stays English. The mock car check knows Albanian words too.
- **2026-11-24 — Listing page extras and "Message seller".** Under the seller card: the city from the seller's profile. Then "Related listings" from `marketplaceService.related` (fits the same car, same brand, same category; best match, then newest). Then "Hide listing": hidden ids live in `MarketplaceContext` (saved on the server later) and are filtered out of the grid and related listings; the seller isn't told. "Message seller" opens the chat with the listing attached above the field and "Përshëndetje, jam i interesuar!" typed in; nothing is sent until you tap Send, which sends the listing card and the message.
- **2026-11-24 — Full-screen listing photos and "Find similar".** Tapping a listing photo opens `app/photos/[id].tsx` (full-screen modal on black, like stories): swipe between photos, pinch to zoom (iOS ScrollView zoom, no new package), × on the left, "7 of 9" top centre. "Find similar" is a quiet pill next to the back button that opens `app/similar/[id].tsx`. Related listings and Find similar share one service call, `marketplaceService.similar(listing, limit)`; the mock scores the car it fits, brand, shared words in title + description, and category (`services/marketplace/similarity.ts`). Later the real search can be smarter (e.g. AI or text search in Postgres) behind the same call.
- **2026-11-24 — Chat attachments: paperclip, previews, aligned composer.** The camera button became a paperclip that opens Photo library (several at once) or Camera (`expo-image-picker`, already installed; camera permission text in `app.json`). Picked photos wait above the field as thumbnails with × and are sent only on Send, in order: listing, photos, text. Buttons and a one-line field are all 40 tall; the field's border sits on a wrapper View (iOS can report a multi-line TextInput taller than it draws), so the buttons stay level with the last line. (Slow typing seen in the simulator was DeviceHub, fixed by quitting it and restarting with a cleared cache, not this code.)
- **2026-11-24 — Read receipts are a flame.** Under your latest message: an unlit grey outline flame + "Delivered", lit red flame + "Seen" (`components/messages/Receipt.tsx`). The word stays so it isn't confused with someone flaming the message. This extends the red rule: red = a flame that's lit (given flame, or seen).
- **2026-11-24 — Red dot on the Marketplace tab for new listings.** `MarketplaceContext` compares `marketplaceService.newestAt()` with when you last opened the Marketplace (`markSeen` on focus); an empty `tabBarBadge` ('') is drawn as a dot by `FloatingTabBar`. Until the server remembers your last visit, listings from the last hour count as new when the app opens; later the backend (and push) will tell the app when new listings arrive.
- **2026-11-24 — Create is a sheet with four choices.** The + opens `app/create/index.tsx` as a bottom sheet (like comments): "What would you like to create?" with Post, Build, Meeting and Crew cards. Picking one closes the sheet and replaces it with `app/create/[kind].tsx` (placeholders until each flow is designed).
- **2026-11-24 — Story camera with `expo-camera` + `expo-video` (approved).** Tapping "Your story" opens `app/story/new.tsx`: a live camera (× / flash / switch camera), a shutter where tap = photo and hold = video (switches the camera to video mode, records up to 15 s, with sound if the microphone is allowed), and the library (photo or video). Then a preview (photo, or the video looping) with Share to your story. Your story lives in `StoriesContext` (`myStory`, `addToMyStory`), plays first when you tap your bubble, and its small + adds more. Video stories play with `StoryVideo` and the bar runs for the video's length. Both packages work in Expo Go; permission texts are in `app.json`. Red is used for the recording state (like LIVE).
- **2026-11-24 — Story editor (no new packages).** After taking or picking, `StoryEditor`: one finger moves the photo / video, two fingers pinch to resize and twist to rotate (`useTransformGesture`, built on React Native's PanResponder, no gesture library), reset puts it back; a row of solid background colours (`colors.storyBackgrounds`, same in both themes) shows behind it; Tag people (@username) and Add location (Kosovo spots + cities + diaspora cities, `data/storyLocations.ts`) add draggable stickers with ×. Saved on the story item as `canvas` (position as share of the screen, scale, rotation, background) and `stickers` (share of the screen), so it looks the same on any phone; the viewer draws them (`StoryCanvasView`, `StoryStickers` above the fade) and @mentions open the profile. If gestures ever feel limited, react-native-gesture-handler + reanimated would be the upgrade (would need approval).
- **2026-11-24 — Your own story: viewers and delete instead of reply.** On your story the footer is "Seen by N" (opens the viewers list: who watched, and a flame next to who flamed it) and ••• (Delete story, removes the photo / video on screen; deleting the last one closes the viewer). Panels open as overlays (`StoryPanel`, a transparent Modal) and pause the story. Viewers are sample data (`data/storyViewers.ts`) until the backend records real views. Camera errors (e.g. "recording isn't supported on the simulator") are caught and shown as a short message instead of an error screen.
